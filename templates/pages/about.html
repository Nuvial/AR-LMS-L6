Overview

The AtkinsRéalis Leave Management System (AR LMS) is a secure and contemporary application aiming to centralise all leave actions within a national organisational scope. The application enables both employees and their respective team managers to oversee and book leave in a hierarchical manner.

The platform is organised around three tiers of access: Employees, Managers, and Admins. Each tier inherits the capabilities of the tier below it, with additional administrative functions layered on top. Access to pages and actions is enforced server-side and adjusted dynamically in the interface to reflect what each role is permitted to do.

Employee Records

Employee records hold the core data for every person in the organisation: name, role, contracted hours, and leave allowances. What you can see and do on this page depends on your access level.

Employee View Record

Standard employees can view only their own record. The overview panel shows their employee ID, name, role, contracted daily and weekly hours, and their default annual and sick leave allowances. A calendar below the overview displays their booked leave for the year, with a table view available via the toggle switch in the panel header. No edits can be made from this page - employee records are managed by admins.

Manager Team Employee Records

Managers see a list of all employees assigned to their team in the left-hand panel. Selecting an employee loads their profile and leave calendar in the overview area. This is a read-only view: managers cannot add, edit, or delete employee records - those actions are restricted to admins.

Admin Full Record Management

Admins have full access to every employee record in the organisation. Beyond viewing, admins can:

  • Add a new employee record via the Add + button in the list panel header.
  • Edit any field on a record - first name, last name, contracted daily hours, contracted weekly hours, default annual leave balance (in hours), and default sick leave balance (in hours) - directly in the overview panel.
  • Delete an employee record permanently. This also removes any linked login account and leave history.

Leave System

The leave system allows employees to request time off and enables managers and admins to action those requests. Three leave types are supported: Annual Leave, Sick Leave, and Time off in Lieu (TOIL).

Booking Leave

To submit a leave request, navigate to Process Leave (or Request Leave for standard employees) from the sidebar. Locate your employee record in the list and select it, then press the Request + button above the calendar. A prompt will ask you to select the leave type, after which you can click or drag a date range on the calendar to define the period.

The system validates the selected period against your contracted daily and weekly hours to ensure the request is reasonable. You may also attach an optional comment with the request. This booking process is identical for all user types - employees, managers, and admins all submit their own leave in the same way.

The system prevents overlapping leave. If you already have a request covering any day within the chosen date range, the submission will be rejected.
Manager Admin Reviewing Leave Requests

Managers and admins see an expanded view of the Process Leave page. The panel lists all employees who have pending leave requests - managers see requests from within their team, while admins see requests from across the entire organisation.

Selecting an employee from this list loads their calendar and highlights their pending requests. Clicking a request from the calendar or table-view opens a detail panel showing the date range, hours requested, current leave balances, and any employee comments. From here, an admin or manager can add their own comment and either Approve or Deny the request.

Managers may only action leave for employees in their direct team. Leave requests submitted by admins must be approved or denied by another admin - a manager cannot action an admin's leave.

Team Management

The Team Management page is accessible to Admins only. It provides a full view of all teams in the organisation and allows admins to create, edit, and delete them.

Creating a Team

Clicking Create Team + adds a new editable row to the team table. A team requires a name and an assigned manager, selected from eligible employees. Team members can be added at creation or later via the edit action. The manager selection is validated to confirm the employee exists and is not already managing another team. A confirmation modal is shown before the new team is saved.

Editing and Deleting Teams

Each team row has edit and delete actions. Editing allows the name, manager, and member list to be updated; unsaved changes can be discarded via the cancel/revert option. Deleting a team is permanent - however, employee records and leave history are preserved; affected employees simply become unassigned from any team.

Hierarchy View

Switching to the Hierarchy tab renders a live flowchart of the entire organisation. Teams appear as blue nodes, managers as purple nodes, and regular employees as dark nodes. Arrows connect each team to its members; a dashed arrow from a manager back to their team indicates their management responsibility. The hierarchy view reloads automatically whenever team data changes.

Login Accounts

Login accounts link an employee record to a set of credentials used to authenticate with the system. An employee record must exist before an account can be created for it. The actions available on the Login Accounts page vary by role.

Self-Registration

Employees can register themselves by visiting the Register page linked from the login screen. Registration requires a company-assigned Employee ID, a chosen username (3-25 alphanumeric characters), and a password (15-128 characters). The account is created in a pending state and cannot be used until an admin approves the request.

Pending registrations appear in the Pending Registrations card on the Login Accounts page, visible only to admins. Each request can be approved (granting access) or denied (removing the pending record). A denied applicant must re-register or have an admin create an account for them directly.

Admin-Created Accounts

Admins can create accounts directly via the Create Account + button on the Login Accounts page. The admin selects an unregistered employee, sets a username, and assigns an initial password. Admin-created accounts are immediately active, but the user is required to change their password on first login.

Forgotten Password

If a user cannot access their account, an admin (or a manager for employees in their team) can reset the password from the Login Accounts page. Once reset, the user will be prompted to set a new password as soon as they next log in.

Manager Account Management

Managers can view the accounts of employees within their direct team hierarchy. They may change the password or change the username of those accounts, and can delete them. Managers cannot create new accounts - a tooltip on the disabled Create Account button explains this restriction.

Admin Full Account Management

Admins have full control over all accounts: creating, editing, promoting, demoting, and deleting. An admin can promote a standard user to admin status or demote an existing admin - both actions require confirmation before taking effect. Admins are also the sole approvers of self-registration requests.

Personal Settings

The Personal Settings page is accessible to all users and provides a view of your own account and employee details. It is available from the sidebar and from the user menu at the bottom of the navigation panel.

The following information is displayed on the settings page:

  • User ID - your unique account identifier within the system.
  • Employee ID - your company-assigned employee record number.
  • First Name - Last Name - editable from this page.
  • Position - your role within the organisation (Employee, Manager, or Admin).
  • Line Manager - the name of your assigned manager, if applicable.
  • Team - the name of the team you belong to, if assigned.
  • Username - editable from this page.

Clicking Edit enables changes to your first name, last name, and username. Changes must be explicitly saved; unsaved edits can be cancelled and reverted at any time.

The Change Password button opens a dialog where you can set a new password. The new password must differ from the current one and meet the length requirements (8-128 characters).

The Delete Account button permanently removes your login account only. Your employee record - including leave history, contracted hours, and other profile data - is not affected and continues to be managed by your line manager or administrator.

Running on the backup server

When the environment tag at the top of the page reads Backup Host, the application is running on its backup host on Render.com rather than the primary server. This automatic failover happens when the primary server is down or temporarily unreachable.

The backup runs on Render's free tier, which uses stateless containers. That means DATABASE PERSISTENCE IS LIMITED. Data written while on the backup host will not be saved between container restarts (details here), and recent changes can be lost once the container spins down or the primary comes back online.

Anything entered during a failover should be treated as temporary. Normal persistence resumes automatically once the primary server is reachable again.
